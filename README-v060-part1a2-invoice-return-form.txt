MSM v0.6.0 — Part 1A.2: полный возврат заявки на счёт

ВАЖНО
Этот патч накатывается ТОЛЬКО поверх уже установленного:
update-v060-part1a-invoice-return.patch

Что меняется
1. Возврат от бухгалтера больше не имеет отдельной логики по причине.
   Причина только объясняет менеджеру, что исправить.
2. При возврате менеджеру снова показываются данные заявки:
   - от кого выставляем;
   - на кого выставляем;
   - позиции и стоимость;
   - комментарий бухгалтерии;
   - ранее отправленный входящий счёт;
   - ранее отправленные документы / реквизиты;
   - флаг «Срочно».
3. Менеджер может изменить данные и повторно отправить ТУ ЖЕ задачу.
4. «Позиции и стоимость» теперь сохраняются при повторной отправке.
5. Можно выбрать новый входящий счёт и добавить новые документы / реквизиты.
6. Отдельное поле «Наценка / цена» убрано из нового запроса и из карточки бухгалтера.
   Условия пишутся в «Комментарий бухгалтерии».
7. Миграция Prisma не требуется.

Файлы
Старые дополнительные вложения физически не удаляются: они остаются в истории сделки.
В этой части мы только возвращаем их менеджеру для просмотра и даём добавить исправленные/новые документы.
Полное управление версиями/повторной загрузкой файлов будет отдельной маленькой частью, чтобы не смешивать изменения.

Применение
cd D:\job\it\msm-app

git apply --check .\update-v060-part1a2-invoice-return-form.patch
git apply .\update-v060-part1a2-invoice-return-form.patch
git diff --check
npm run build

Если git apply --check или npm run build выдаст ошибку — дальше не продолжать и прислать полный вывод.

Что проверить после зелёного build
1. Менеджер отправляет запрос с позициями, комментарием, входящим счётом и документом/реквизитами.
2. Бухгалтер возвращает его по любой причине.
3. Менеджер открывает сделку и видит все эти данные.
4. Менеджер меняет позиции/комментарий или прикладывает исправленный файл.
5. Нажимает «Сохранить и повторно отправить».
6. У бухгалтера появляется та же задача с обновлёнными данными, без дубля.

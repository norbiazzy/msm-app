v0.6.0 Part 1N-I1 — рабочее место запроса счёта внутри задачи

Идея:
Сделка = общая карточка процесса.
Задача = конкретное действие со всеми данными, нужными для выполнения.

Что меняется:

1. Бухгалтер открывает задачу «Выставить счёт»
и прямо в ней видит блок «Данные для выставления»:
- ЗК / клиент
- от кого выставляем: СТ / МСМ / ИП
- на кого выставлять
- условия
- значение наценки / скидки
- плановую дату отгрузки
- контакт
- текст запроса
- комментарий бухгалтерии
- адреса
- входящий счёт
- дополнительные документы

Старый бухгалтерский функционал выставления готового счёта
в TaskDetail сохраняется.

2. Если бухгалтер вернул задачу менеджеру
ISSUE_CLIENT_INVOICE со статусом NEED_DATA
открывается отдельная форма исправления прямо в «Задачах».

Менеджер может исправить:
- от кого выставляем
- на кого выставлять
- условия
- значение
- комментарий бухгалтерии
- срочность
- новый входящий счёт
- дополнительные документы

3. Повторная отправка
Используется существующая логика:
updateDealInfo + submitInvoiceRequest.

Поэтому:
- используется ТА ЖЕ активная ISSUE_CLIENT_INVOICE task;
- новая задача не создаётся;
- после отправки status возвращается в NEW;
- assigneeId очищается существующей логикой;
- бухгалтер снова получает ту же задачу.

4. Файлы
Если есть новые файлы:
- менеджер сразу возвращается в список задач;
- прогресс показывается на этой task;
- новый входящий счёт -> CUSTOMER_INVOICE_PRIMARY
- дополнительные документы -> TASK_ATTACHMENT_<taskId>
- после загрузки та же задача повторно отправляется бухгалтерии.

5. Сделка
Установщик пытается автоматически убрать большую форму исправления
из DealDetail и оставить переход в задачу.
Если локальный JSX отличается, --check прямо сообщит,
что task-форма работает, но блок сделки не был автоматически скрыт.

Backend не меняется.
Prisma migration не нужна.

Установка:
1. Распаковать ZIP в:
D:\job\it\msm-app

2. Проверка:

3. Если OK:
node .\apply-v060-part1n-i1-invoice-task-workspace.cjs

4. Проверка:

5. Frontend:
